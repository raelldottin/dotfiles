Declarative workstation configuration for macOS and Linux using Nix, Home Manager, nix-darwin, and nix-homebrew.

## Migration Status

The Nix migration is currently staged on `dev`.

- `main` remains the pre-Nix stable configuration.
- `dev` contains the Nix/Home Manager migration.
- CI validates the flake, Linux Home Manager output, and Apple Silicon nix-darwin output.
- The legacy shell/Python installer remains available as a rollback path.
- Promotion from `dev` to `main` is gated on a successful activation on the real Mac.

This keeps the migration reversible while changing the system that manages the workstation itself.

## macOS

The macOS configuration targets Apple Silicon and is exposed as:

```text
.#macbook
```

### First Activation

Use the `dev` branch while the migration is being validated:

```bash
git switch dev
git pull

nix flake check

sudo nix run nix-darwin/nix-darwin-26.05#darwin-rebuild -- \
  switch --flake .#macbook
```

During the first activation, Home Manager backs up conflicting managed files using the `.hm-backup` suffix.

The migration intentionally does not remove unlisted Homebrew software. Existing formulae and casks remain in place while the Nix configuration is proven on the workstation.

### Normal Rebuild

After nix-darwin is installed:

```bash
sudo darwin-rebuild switch --flake .#macbook
```

### Update Pinned Inputs

```bash
nix flake update
nix flake check
sudo darwin-rebuild switch --flake .#macbook
```

Review `flake.lock` before committing an input update.

## What Nix Manages

Home Manager currently owns:

- zsh
- Oh My Zsh
- zsh autosuggestions and syntax highlighting
- Powerlevel10k
- tmux
- tmux plugins
- Neovim configuration
- `~/.pylintrc`
- core CLI and development packages

On macOS, nix-darwin and nix-homebrew additionally manage system integration and selected GUI casks.

## Homebrew Strategy

Homebrew is not being removed.

It remains useful for macOS GUI software while command-line and development tooling moves toward nixpkgs. The current migration uses:

```nix
homebrew.onActivation.cleanup = "none";
```

That prevents the first activation from deleting Homebrew software that has not yet been classified into the Nix configuration.

Once the migration is proven, the remaining Homebrew inventory can be reviewed and either moved into Nix, retained as a cask, or removed.

## Rollback

The legacy installer remains available until the Nix configuration has been activated successfully on the workstation.

```bash
make dependencies
make install
make verify-install
```

Do not delete the legacy installer, its package inventories, or its compatibility tests until the macOS activation has been verified.

## Migration Completion Criteria

The migration can move from `dev` to `main` after:

1. `darwin-rebuild switch --flake .#macbook` succeeds on the real Mac.
2. zsh starts normally.
3. tmux loads its expected plugins and bindings.
4. Neovim starts with the existing configuration.
5. expected CLI development tools are available.
6. Homebrew GUI applications remain intact.
7. a second rebuild completes cleanly and demonstrates idempotence.

After that, the legacy shell/Python installer and obsolete package inventory files can be removed in a separate cleanup change.
